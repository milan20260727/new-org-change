# 组织架构调整 Demo

一个组织架构可视化调整工具的交互原型：在图上编辑组织架构（重命名 / 移动 / 删除 / 新增），维护部门角色（PIC / HRBP1 / HRBP2 / Department Assistant），管理下辖员工，并生成可直接粘贴回 Base 的变更记录。

## 这是什么、不是什么

这是一个**纯前端交互原型**，用来验证组织架构调整这套流程的界面设计和操作逻辑，不是可以直接上线使用的产品：

- **登录是模拟的**：点击"使用飞书账号登录"只是一个 700ms 的假加载，不会跳转真实的飞书 OAuth。
- **数据是写死的快照**：内置的 10 个组织节点、15 名员工、角色信息，取自公司 Base 里「Lark Structures」+「Employee list」+「Lark User」三张表的一份真实子集（Central → Investor Relations Corporate Communications and Sustainability），但只是导出时的一份静态快照，页面不会连接任何真实的 Lark / Base 接口。
- **不会写回任何地方**：所有操作只在浏览器内存里生效，刷新页面即恢复初始状态；"复制变更 / 下载 CSV"导出的内容需要人工核对后手动贴回 Base。

如果需要接真实的飞书登录、真实读写 Lark Base，请看下面「和 org-chart-live 的关系」。

## 快速开始

不需要构建，也不需要安装依赖，用任意静态文件服务器打开 `index.html` 即可（直接双击用 `file://` 打开也能跑，但浏览器剪贴板 API 在部分场景下需要 `http(s)://`，建议起一个本地服务器）：

```bash
npx serve .
# 或者
python -m http.server 8080
```

然后在浏览器打开对应地址，点"使用飞书账号登录"进入。

## 功能一览

- **组织架构图**：卡片式节点 + 圆角折线连接（共用主干、非交叉曲线），支持纵向 / 横向切换、按名称搜索聚焦到某个子树、拖拽节点直接发起移动
- **编辑类型**（重命名 / 移动 / 删除）：同一次保存里三选一或自由组合重命名 + 移动，删除与其他类型互斥；移动的目标下拉列表会自动排除自身及所有子部门，避免循环嵌套
- **新增子部门**：独立的"+"入口（不和其他编辑类型混在一起），新增时可以一并把角色也设置好
- **角色管理**：PIC / HRBP1 / HRBP2 / Department Assistant 只能从 Lark User 名单里搜索指定；支持一键把当前部门的 HRBP1/HRBP2/Department Assistant 应用到所有下级部门；自动检测某个分支下角色是否不一致或存在空值并提示
- **删除前安置员工**：部门下有员工时不能直接删除，需要先给每个人指定新部门（支持单个指定或批量转移到同一个部门）；撤销删除会把这批员工自动迁回原部门
- **员工调动**：下辖员工名单里勾选后批量转移，也可以用顶部"转移员工"按钮按姓名 / EID 搜索单独调动
- **净变化对比**：重命名 / 移动 / 角色变更如果在同一次会话里来回改、最终变回原样，不会在变更记录里留痕迹；多次移动只保留"原始位置 → 最终位置"这一条净结果，不记录中间过程
- **移动部门时提示同步汇报关系**：如果被移动部门设有负责人（PIC），且移动后其"名义上级"发生变化，会提示是否同步更新该负责人的直属汇报对象，需要人工确认，不会自动静默修改
- **导出**：变更记录 / 受影响员工清单支持一键复制（TSV，可直接粘贴进 Base 表格）或下载 CSV；组织架构图支持导出 PNG（手工在 canvas 上逐个绘制节点和连线，不依赖把 DOM 转图片，避开了 Chromium 对含 `<foreignObject>` 的 SVG 图片判定为"污染 canvas"而拒绝导出的问题）

## 项目结构

```
index.html      页面结构
css/style.css   样式（含亮 / 暗色主题变量）
js/app.js       全部交互逻辑，无外部依赖，纯 vanilla JS
```

## 和 org-chart-live 的关系

公司内部已有一个功能更完整、真正接了飞书登录和 Lark Base 读写的项目 **org-chart-live**（`github.com/milan20260727/org-chart-live`）。这个仓库和它是两条独立的线：

- `org-chart-live`：真实登录、真实数据、真实写回，面向实际使用
- `new-org-change`（本仓库）：交互设计原型，用来快速试错 UI 和操作流程，数据和登录都是假的

这里验证过的交互点（净变化对比展示、删除前安置员工、移动部门提示同步汇报关系等）如果确认有效，需要人工移植到 `org-chart-live` 的真实代码里，本仓库不会自动同步过去。
